Standing rule (Shoaib, 2026-10-06): for **every client project**, record each piece of work as it is done, so a professional month-end report can be sent to the client.

What counts:
- audits
- website work and fixes
- graphic design
- social media posts
- ads plans, launches, optimisations and **results**
- GBP work
- tracking and analytics setup
- anything else delivered

**Why:** clients get a monthly report of what was done and what it achieved. Nothing should be lost between sessions, and the report must look professional.

**How to apply:**
- Where to log: the client's KB project (kb_* MCP), doc `marketing_doc` slug `client-report-log-YYYY-MM` (e.g. `client-report-log-2026-10`), using `mode: append`.
- Each entry is dated and written client-facing in plain English:
  - **Area:** Ads / Website / Design / Social / GBP / Tracking / Audit.
  - **What was done:** one or two lines, no internal jargon, no IDs or tokens.
  - **Why it matters / result:** numbers when available (spend, chats, calls, bookings, cost per booking).
- Log in the same session the work happens. Don't batch at month end.
- Internal notes (IDs, gotchas) stay in the memory / work log, not in the client log.
- If a project has no KB project yet, add the entry to that project's memory notes and create the KB doc when the project exists.
- Month end: build the report (PDF or page) from this log plus the platform results.
- Never claim results that aren't measured.
