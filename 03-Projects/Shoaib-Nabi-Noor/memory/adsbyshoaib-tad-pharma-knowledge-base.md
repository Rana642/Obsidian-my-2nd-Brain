Built 2026-09-24 (commit `b10bca7`, pushed). Shoaib's ask: ingest Tad Pharma's product literature PDFs + finished-product photos into the dashboard, invisible in the UI but fully usable via MCP so a chat-driven generation call has real facts (not hallucinated ones) about brand positioning, ICP, pain points, and exact product data.

**Data model**: two new Supabase tables (`supabase/dashboard-schema.sql`), both keyed to `client_projects(id)` (project 15502bc4-2855-4f5c-bc85-36c5dcb3e9d3 = "Tad Pharma", client Ahmed Jahanzaib Shah — see [[adsbyshoaib-social-poster]] for the client→project re-scoping this reuses):
- `project_knowledge_docs` (doc_type: brand_position/icp/pain_points/graphic_rules, one row per type per project, markdown content).
- `project_products` (name/slug/category/markdown content/image_key, one row per SKU).
Both RLS-enabled with zero policies (service-role only), same convention as the rest of the dashboard schema.

**Source material**: `Tad pharma literature pdf/` (17 PDFs, scanned images — no text layer, had to render each page to PNG via PyMuPDF since poppler/pdftoppm isn't installed on this machine, then read visually) and `Finish Product Tad pharma/` (15 finished-product PNGs). Both folders are now gitignored (raw material already ingested into the DB, redundant to track). One PDF was misleadingly named `Document 41.pdf` — actually Gumbonil's literature; caught by reading it rather than trusting the filename.

**Products ingested (17)**: Aminotox, Ampotad, Biofurose, Bromotyl-68, Gumbonil, Enroline 20, Florise-23, Fosfolide-20, Li Tonic, Lysorox, Necloxy-50, Niflorise, Reevit E-Se 100, Reevit K3, Reevit C 500, Seno Tad-TS, Tilmorise — composition/indications/dosage copied verbatim from the manufacturer literature (never approximated — this is regulated veterinary medicine). **Important context discovered while reading the PDFs, corrects an earlier assumption**: Tad Pharma is a **veterinary/poultry** pharma distributor (sole distributor in Pakistan for REEFCO Jordan and Lexington Singapore), not human pharma — every product is labeled "Vet — Not for human, veterinary use only." Target customers are poultry farms/vets/feed dealers, not human patients.

**Strategic docs (brand_position, icp, pain_points) are explicitly marked as DRAFTS** synthesized only from what the literature/public facts actually state, with an "Ahmed/Shoaib should review and correct" note at the top of each — deliberately not asserted as verified fact, per the no-fabrication rule for pharma content (see [[adsbyshoaib-privacy-policy-api-compliance]] for the same principle applied elsewhere). **Graphic rules doc** pulls real hex values from the separate `tad-pharma` repo's `app/globals.css` (red #ED1C24, deep red #C41319, charcoal #231F20, green #2E9E5B; fonts Archivo/Inter) plus recurring layout conventions observed across the literature (composition block, dosage split prevention/treatment, Urdu translation column, "Sole Distributer in Pakistan" footer, veterinary-only disclaimer) — this is what Graphic Studio generations for this brand should follow.

**MCP tools** (new `lib/mcp-knowledge-tools.ts`, shared by both servers like [[adsbyshoaib-mcp-marketing-tools]]): `kb_list_projects`, `kb_get_brief` (project name → combined docs + product list), `kb_list_products`, `kb_get_product` (returns markdown + the product photo as an image content block, fetched from R2 via `lib/storage.ts`'s `fetchObject`). Registered in `mcp/index.ts` (local stdio, re-exported via `mcp/tools/knowledge.ts`) AND `app/api/mcp/route.ts` (remote OAuth connector) — both paths verified live via a throwaway stdio smoke-test script (listed tools, called `kb_get_brief` and `kb_get_product`, confirmed real text + image content came back, script deleted after).

**Deliberately NOT in the dashboard UI** — Shoaib: "beshak kahen nazar na aye lakin mcp mai zaror reflect ho aur isko utilize kiya ja sky" — this is intentional, don't add a `/dashboard/knowledge` page unless he asks.

**Pattern for future projects**: this is designed to be repeatable — any client_project can get the same two tables populated (schema is generic, not Tad-Pharma-specific) if Shoaib asks for another brand's knowledge base later. See [[socially-snap-saas-plan]] — this knowledge base stays dashboard-only, never gets wired into either SaaS product (Socially Snap or Graphic Studio) per Shoaib's explicit scoping.
